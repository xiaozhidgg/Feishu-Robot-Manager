# 飞书群聊 DeepSeek 机器人

在飞书群里 @ 机器人 → 机器人带着上下文调用 DeepSeek → 回复到群里。

**长连接（WebSocket）模式**：不需要公网 IP、不需要域名、不需要内网穿透，本地 Windows 电脑上 `npm start` 就能跑通。

---

## 一、先搞清楚三条路，别走错

| 方案 | 能否「在群里对话」 | 说明 |
|---|---|---|
| 群自定义机器人（Webhook） | ❌ 只能单向推送 | 在群设置里加个 Webhook 地址，只能往外发通知，收不到成员消息，做不了聊天 |
| **企业自建应用 + 长连接**（本项目） | ✅ 推荐 | 正式机器人：能收群消息 / 单聊消息，能回复、能引用、能发卡片。无需公网服务器 |
| 企业自建应用 + HTTP 回调 | ✅ | 需要在开放平台填一个公网可访问的回调地址，要备案域名或内网穿透，比长连接麻烦 |
| 扣子 / Dify 等平台一键发布到飞书 | ✅ 但不可控 | 适合零代码试用，提示词、上下文、权限都受平台限制 |

## 二、飞书侧配置（约 10 分钟，一次性）

### 1. 创建自建应用
打开 <https://open.feishu.cn/app> → **创建企业自建应用** → 填名称（如 `DeepSeek 助手`）、图标 → 创建。

进入应用后，在 **凭证与基础信息** 页记下：

- `App ID`（cli_ 开头）
- `App Secret`

### 2. 添加「机器人」能力
左侧 **添加应用能力** → 找到 **机器人** → **添加**。

### 3. 开通权限
左侧 **权限管理** → 搜索并开通以下权限（缺一不可）：

| 权限码 | 用途 |
|---|---|
| `im:message.p2p_msg:readonly` | 接收用户发给机器人的**单聊**消息 |
| `im:message.group_at_msg:readonly` | 接收群里 **@机器人** 的消息 |
| `im:message:send_as_bot` | 以机器人身份**发消息** |
| `im:chat:readonly` | （可选）读取群基本信息 |

> 群聊默认只推送 @ 机器人的消息，这是有意的设计，也更省 Token。
> 想让它"监听群里所有消息不 @ 也回复"，需要额外申请 `im:message.group_msg`——这是**敏感权限**，通常要企业管理员额外审批，且会产生大量调用。一般不建议。

### 4. 配置事件订阅（关键一步）
左侧 **事件与回调** → **事件配置**：

1. **订阅方式** 选择 **「使用长连接接收事件」**（不是"将事件发送至开发者服务器"）
2. 点击 **添加事件** → 搜索 `接收消息` → 勾选 `im.message.receive_v1`

> 选了长连接就不需要填 Request URL，也就不用管 Encrypt Key / Verification Token 了。

### 5. 发布版本
左侧 **版本管理与发布** → **创建版本** → 填版本号（如 `1.0.0`）→ 申请发布。
自建应用需要**企业管理员审核通过**（若你自己是管理员，去飞书管理后台「应用管理」里通过即可）。

### 6. 把机器人拉进群
- 方式一：在飞书群里 → 右上角 **···** → **设置** → **群机器人** → **添加机器人** → 搜索应用名
- 方式二：应用后台把**可用范围**设为全员，成员即可自行添加

## 三、本地运行

**最简单：双击 `启动飞书机器人.bat`（在工作区根目录）或 `feishu-deepseek-bot\启动机器人.bat`。**
脚本会自己切到项目目录、检查 `.env`、缺依赖自动装、然后启动。

想先体检不自启，加 `--check` 参数：

```bat
cd feishu-deepseek-bot
启动机器人.bat --check
```

会打印工作目录、Node 版本、`.env` 是否就绪、依赖是否安装、凭证是否填好，不启动机器人。

**命令行手动跑：**

```bash
cd feishu-deepseek-bot
npm install
copy .env.example .env      # Windows；macOS/Linux 用 cp
# 编辑 .env，填入 App ID / App Secret / DeepSeek API Key
npm start
```

> ⚠️ 注意 `cd` 一定要先切进 `feishu-deepseek-bot` 目录。停在 `C:\Users\EDY` 直接敲 `npm start` 会报 `ENOENT ... package.json`——npm 是按**当前目录**找 `package.json` 的。
>
> ⚠️ 批处理文件必须是 **GBK 编码 + CRLF 换行**。用 UTF-8 保存的 .bat，cmd 解析中文会错位，出现 `'ho' 不是内部或外部命令` 这种莫名其妙的分裂报错。

看到这行就成功了：

```
🚀 DeepSeek 机器人已启动，模型 deepseek-flash，正在等待飞书消息…
```

然后到群里 **@DeepSeek 你好** 试一下。

## 四、配置项说明（.env）

| 变量 | 说明 |
|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书应用的凭证 |
| `DEEPSEEK_API_KEY` | 在 <https://platform.deepseek.com> 申请 |
| `DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com`，走代理时改这里 |
| `DEEPSEEK_MODEL` | 默认 `deepseek-flash`；复杂推理可用 `deepseek-v4-pro` |
| `BOT_NAME` | 机器人自称，用于 /help 文案 |
| `SYSTEM_PROMPT` | 人设 / 公司知识，改成你想要的风格 |
| `MAX_HISTORY_TURNS` | 保留最近 N 轮上下文；`0` = 每句话都是独立提问，最省 Token |
| `WEB_SEARCH` | `on` 开启联网搜索（默认 `off`）；需要 `DEEPSEEK_API_KEY` |
| `WEB_SEARCH_MAX_RESULTS` | 每次返回条数，默认 `5` |

## 四之二、联网搜索（可选）

在 `.env` 里加两行就能开：

```ini
WEB_SEARCH=on
WEB_SEARCH_MAX_RESULTS=3
```

- 搜索与网页抓取都由 DeepSeek 官方接口完成，复用同一个 `DEEPSEEK_API_KEY`，不需要额外注册搜索服务。
- 开启后机器人多出两个工具：`web_search`（关键词搜索，带日期与摘要）、`fetch_url`（抓网页正文，截断 6000 字），模型只在问题需要实时信息时调用；结论里会带 `[标题](链接)`。
- 接口：`POST /v1/tools/search`（`query`、`count`、`need_content`）、`POST /v1/tools/fetch`（`url`），`Authorization: Bearer <DEEPSEEK_API_KEY>`。
- 同一 query 结果缓存 10 分钟、最多 200 条；超时/HTTP 错误会以中文原因返回给模型，让它自己决定要不要换个说法再搜。
- 实现：`search.js`（工具定义 + 缓存 + 抓取），`index.js` 里注册进工具列表并在启动日志里打印「联网搜索 已开启/未开启」。
- 用管家的话，插件页「联网搜索」可以直接开关、改条数、测试接口，不用手改 `.env`。

## 四之三、表格

回答里可以带表格，但**飞书纯文本消息不支持表格**，所以带表格的答案会改成「消息卡片 + 表格组件」发送：

- 模型输出 Markdown 表格（`| 表头 | ... |` + `| --- |` 分隔行）即触发；`tablecard.js` 负责把文本拆成「段落 + 表格」，拼成卡片 JSON。
- 流程：先发的「🤔 正在思考…」占位消息会被**撤回**，再在同一个话题下发卡片；撤回失败时退化为把占位改成「表格整理好了，见下一条 👇」。
- 表格超过 10 行时由客户端分页（`page_size`），不是截断；不含表格的答案仍走原来的纯文本回填，样式不变。
- 代码块里（``` 包起来）的 `|` 不会被误判成表格；只有表头没有数据行、或缺少分隔行的，也不算表格。
- 想让模型更爱用表格，人设或提问里说清楚「列个表 / 对比一下」即可；`index.js` 已经在系统提示里加了一句表格约定。

**卡片的三道保险**（飞书对卡片很挑，参数不合规直接 400，用户那边什么都收不到）：

| 情况 | 处理 |
| --- | --- |
| 表格超过 9 列 | 不塞表格组件，降级成 Markdown 管道表格（`MAX_TABLE_COLS`） |
| 卡片 JSON 超过 26KB | 整条改发纯文本（`isCardTooBig`） |
| 卡片发送仍然 400 | 记下 `e.response.data` 里的真实原因，并把内容按纯文本重发一遍（`settle` 里的降级分支） |

单元格会先做清洗：换行压成空格、去首尾空白、截断到 300 字 —— 飞书表格组件不接受多行单元格。

## 四之四、引用回复

用户在飞书里「引用」一条消息来提问时，事件里只有 `parent_id`，没有正文。`index.js` 的 `fetchQuoted()` 会按这个 id 把被引用那条拉回来（`im.v1.message.get`），拼成：

```
[我引用的消息]
<被引用的内容>

[我的问题]
<用户这次打的字>
```

- 支持引用文字、富文本（post）、图片；图片会被下载下来一起送进模型（受 3 张图片上限约束）。文件 / 语音 / 视频 / 合并转发只留一句占位说明。
- 拉取结果按 message_id 缓存 10 分钟（最多 20 条），同一条被反复引用不会反复请求。
- 读取失败只是少一段上下文，不影响回答；日志里会有一行 `[引用] 读取失败：…`。
- 需要机器人有读消息的权限（`im:message` 或 `im:message.group_msg`）。没权限时这条路径静默降级。

## 五、实现要点（改代码前先看这段）

1. **3 秒内必须 ACK**
   飞书要求事件回调 3 秒内响应，否则会重推。所以 `index.js` 里事件回调**立刻 return**，真正的模型调用放到后台异步跑。

2. **消息去重**
   重推会导致同一句话被回答两次。代码里用 `message_id` 做了 10 分钟窗口的去重。

3. **@ 占位符要剥掉**
   群消息的 content 长这样：`{"text":"@_user_1 帮我写个周报"}`，`@_user_1` 是机器人自己。不剥掉会污染提示词,代码里正则 + `mentions` 双重清理。

4. **先占位再回填，体验更好**
   模型返回通常要几秒。代码先引用回复一条「🤔 正在思考…」，拿到答案后用 `message.update` 把这条消息改成答案，群里看起来是"就地变成回答"。更新失败会自动降级成发新消息。

5. **上下文隔离**
   单聊按 `chat_id` 存；群聊按 `群 + 发送人` 存，避免 A 的追问接在 B 的问题后面。闲置 30 分钟自动过期。

6. **超长回答自动分段**
   单条文本消息有长度限制，超过 3000 字会拆成多条引用回复。

7. **图片消息**
   - 支持 `image`（单图）和 `post`（图文混排，取前 3 张图）。飞书里"截图 + 一句话"发出去，类型往往就是 `post`，不处理会漏。
   - 流程：`im.v1.messageResource.get` 拿二进制流 → base64 data URL → 塞进 `image_url` 内容块。
   - 格式按**文件头**判断（PNG/JPEG/GIF/WebP），不信 `content-type`。
   - 用 `detail: 'high'`：DeepSeek 反正会把每张图压到约 800×800、最多 384 token，清晰度优先不吃亏。实测一张 72KB 截图，图文合计 487 prompt tokens。
   - 历史里只存 `[用户发送了 N 张图片]` 占位，不存 base64，否则几轮之后上下文就爆了。
   - 看不了：文件、语音、视频、表情包、合并转发里的图片。

   > 前提是模型支持视觉。`deepseek-flash`（V4.1 Flash）原生多模态；换成不支持图片的模型会返回 400。

## 六、让它管飞书云文档

先纠正一个常见误解：**飞书没有"列出应用可见的全部文档"这种接口**。
应用身份（tenant_access_token）能看到什么，完全取决于「谁把哪篇文档授权给了这个应用」。所以「让它知道自己能控制哪些文档」只能靠三条路组合：

| 路径 | 机器人怎么"知道" | 适合 |
|---|---|---|
| 白名单 `docs.json` | 人工登记文档名 + 链接，启动时注入系统提示 | 固定几篇常用文档，最稳 |
| `search_docs` 工具 | 调飞书搜索接口按关键词找有权限的文档 | 文档多、经常变 |
| 群里直接甩链接 | 解析 URL 得到 token，再受文档自身权限约束 | 临时一次性 |

代码里这三条都实现了，模型会按需要自己选。

### 6.1 开通权限（不开就什么都看不到）

权限管理里加这几项，然后**重新发布版本**：

| 权限码 | 用途 |
|---|---|
| `docx:document` | 读写文档正文与块 |
| `docx:document:create` | 新建文档 |
| `drive:drive` | 云空间（列举、权限管理） |
| `search:docs:read` | 搜索文档 |
| `wiki:wiki:readonly` | 解析知识库节点（文档在知识库里时需要） |

开完可以用 `node check-perms.mjs` 逐个验证哪个接口通了、还缺哪个 scope。

### 6.2 把文档授权给机器人

文档 → 右上角 **分享** → **添加协作者** → 搜索你的应用名（如 `DeepSeek 助手`）→ 权限选「可编辑」。
或者把文档发到机器人所在的群（部分场景会随群继承）。

> 注意：给**应用**授权 ≠ 给应用里的每个用户授权。机器人拿到的是应用级权限，跟谁在群里问无关。

### 6.3 登记白名单

```bash
copy docs.example.json docs.json
```

填 `name` / `url` / `writable`：

```json
{
  "docs": [
    { "name": "周报", "url": "https://xxx.feishu.cn/docx/DoxcnXXXX", "writable": true },
    { "name": "规章制度", "url": "https://xxx.feishu.cn/docx/DoxcnYYYY", "writable": false }
  ]
}
```

登记完重启，会发生三件事：

1. 系统提示里自动带上这份清单，模型不用"猜"有哪些文档；
2. 群里发 `/docs` 直接回清单；
3. 「把今天结论追加到周报」→ 模型自己调 `append_doc`；「周报第 3 条写了啥」→ 调 `read_doc`。

### 6.4 工具一览

| 工具 | 作用 |
|---|---|
| `list_docs` | 列出白名单里的文档 |
| `search_docs` | 搜索有权限的文档 |
| `read_doc` | 读 docx 正文，或读电子表格（可传 `query` 关键词只取相关行） |
| `append_doc` | 在 docx 末尾追加段落（表格写入未开放） |
| `create_doc` | 新建 docx 文档 |

工具调用最多 5 轮，失败会把可读原因回给模型（而不是直接崩），模型会转述给你，比如「应用缺少权限：search:docs:read」。

### 6.5 三个限制，提前知道

1. **没授权的文档碰不到**，返回 403 / `1770032`，代码已翻译成中文提示；
2. **知识库文档**要走 `wiki` 节点换 `obj_token`，代码已处理，但机器人得是那个知识库的成员；
3. **只能追加，不能改写**。`append_doc` 是往末尾加段落；要改已有内容得用 `documentBlock.patch` 逐个块改，目前没实现。
4. **表格只读不写**。电子表格（含知识库里的 sheet）能读：`sheets.v3` 拿工作表列表 + `sheets/v2 values` 读单元格，读回来按「第 N 行：a | b | c」输出；带 `query` 时只返回命中的行（连同上一行分组标题），避免整表塞满上下文。往表格写数据还没做。
5. 表格数据有 60 秒缓存，同一篇文档连问几次不会重复拉全表。

## 七、常见问题

**启动报 `10003 invalid param` / `app not found`**
App ID 或 Secret 填错，或者应用还没发布（开发中也要先在后台创建版本并发布）。

**能连上，但日志里打印 `receive events or callbacks through persistent connection only available in self-build & Feishu app`**
这条是飞书服务端返回的，意思是"这个应用不能用长连接收事件"。两种原因：
1. 「事件与回调 → 订阅方式」还停在"将事件发送至开发者服务器"，没切成 **「使用长连接接收事件/回调」**；
2. 应用不是**企业自建应用**（比如是商店应用）。
改完订阅方式后**必须重新创建版本并发布**才生效。

**能连上但群里 @ 没反应**
1. 机器人没被拉进群；
2. 权限没开全（尤其 `im:message.group_at_msg:readonly`）；
3. 事件订阅里没勾 `im.message.receive_v1`；
4. 版本发布的权限变更**还没生效**——改了权限必须**重新创建版本并发布**。

**回复 `❌ 调用模型失败：HTTP 401`**
DeepSeek API Key 错误或余额不足。

**提示 `HTTP 400 model not exist`**
模型名写错了。当前可用的是 `deepseek-flash` 和 `deepseek-v4-pro`（`deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 停用）。

**一台机器跑多个实例会重复回复吗？**
不会重复，但长连接是集群模式——同一应用多个客户端时，只有**随机一个**收到消息。要做多实例负载均衡请改用 HTTP 回调。

**要不要一直开着电脑？**
长连接是本地进程，关掉就下线。要 7×24 运行，把项目丢到一台常开的服务器 / 云主机上跑 `node index.js`，或注册成 Windows 服务（`nssm install`）。
